# CustomTkinter Desktop App Template

[![repository](https://img.shields.io/badge/GitHub-repository-blue?logo=github)](https://github.com/ExtaSsS4106/Customtkinter_desctop_app_template)

Базовый шаблон desktop-приложения на Python и CustomTkinter. Проект содержит готовую структуру для оконного приложения, переключение экранов, формы входа и регистрации, переиспользуемые UI-компоненты, демонстрационную витрину виджетов CustomTkinter и централизованные настройки внешнего вида.

> Текущая версия является учебным и стартовым шаблоном. Пользователи не сохраняются в базе данных, API не подключён, а проверка входа использует демонстрационные данные из исходного кода.

## Назначение

Шаблон предназначен для быстрого запуска небольших настольных приложений на Python с графическим интерфейсом. В текущем виде он демонстрирует:

- главное окно на базе `customtkinter.CTk`;
- минимальный роутер экранов с переключением по именам;
- отдельные экраны входа и регистрации;
- проверку обязательных полей, email и пароля;
- обработку нажатия `Enter` в формах;
- централизованные фабрики полей, кнопок и сообщений об ошибках;
- тёмный режим и синюю цветовую тему CustomTkinter;
- витрину основных виджетов CustomTkinter;
- ограничения минимального и максимального размера окна;
- заготовки для подключения базы данных, API и реальной авторизации.

## Возможности текущей версии

### Вход

Экран входа находится в `src/forms/authorisation/authorisation.py` и содержит:

- поле логина или email;
- поле пароля;
- кнопку `Войти`;
- переход на регистрацию;
- проверку заполнения полей;
- проверку минимальной длины пароля в 6 символов;
- очистку пароля после неуспешной попытки;
- вход по клавише `Enter`.

Для демонстрации используется следующая пара:

```text
Логин: admin
Пароль: admin123
```

При успешном входе приложение переключается на экран с маршрутом `dashboard`. В текущем реестре маршрутов такой экран ещё не добавлен, поэтому перед использованием успешного сценария необходимо зарегистрировать страницу `dashboard` или заменить переход на существующий маршрут.

### Регистрация

Экран регистрации находится в `src/forms/authorisation/registration.py` и содержит поля:

- имя пользователя;
- email;
- пароль;
- повтор пароля.

Проверки регистрации:

- все поля должны быть заполнены;
- имя пользователя должно содержать минимум 3 символа;
- email проверяется регулярным выражением базового формата;
- пароль должен содержать минимум 6 символов;
- пароль и подтверждение должны совпадать.

После успешной локальной проверки имя и email выводятся в консоль, а приложение переключается на экран входа с предварительно заполненным логином. Фактического сохранения пользователя пока нет: в коде оставлен комментарий `TODO` для подключения базы данных или API.

### Витрина компонентов

`src/forms/components_demo.py` содержит демонстрационный экран виджетов CustomTkinter. На нём показаны:

- `CTkLabel`;
- `CTkButton`;
- `CTkEntry`;
- `CTkCheckBox`;
- `CTkRadioButton`;
- `CTkSwitch`;
- `CTkSlider`;
- `CTkProgressBar`;
- `CTkComboBox`;
- `CTkOptionMenu`;
- `CTkTextbox`;
- `CTkSegmentedButton`;
- `CTkTabview`;
- переключатели режима оформления и цветовой темы.

Изменение темы на этом экране выполняется глобальными функциями `ctk.set_appearance_mode` и `ctk.set_default_color_theme`.

## Требования

- Python 3.10 или новее;
- `pip`;
- Tkinter, доступный в системе;
- зависимости из `req.txt`.

В Linux для работы Tkinter может потребоваться системный пакет `python3-tk`:

```bash
sudo apt install python3-tk
```

Точная версия Python в проекте отдельно не зафиксирована. Перед использованием в production рекомендуется выбрать и закрепить поддерживаемую версию в документации или конфигурации CI.

## Установка

Команды выполняются из корня репозитория:

```bash
python -m venv venv
```


```powershell

```

```bash
python -m pip install --upgrade pip

```

## Запуск

Запуск приложения:

```bash
python main.py
```

Окно приложения по умолчанию открывается размером `600x400`. Минимальный размер окна также составляет `600x400`, максимальный — `1200x900`.

В Linux при ошибке вида `No module named tkinter` установите системный Tkinter и повторите запуск.

## Зависимости

Файл зависимостей называется `req.txt` и содержит:

```text
customtkinter==6.0.0
darkdetect==0.8.0
packaging==26.3
pillow==12.3.0
```

`customtkinter` предоставляет современные виджеты поверх Tkinter. `darkdetect` используется CustomTkinter для определения системного режима оформления. `packaging` и `pillow` являются зависимостями окружения CustomTkinter и работы с изображениями.

## Архитектура

Точка входа `main.py` выполняет минимальную инициализацию:

1. импортирует формы;
2. создаёт объект `App`;
3. вызывает `app.init_page()`;
4. запускает цикл обработки событий через `app.mainloop()`.

Класс `App` в `conf/app.py` наследуется от `customtkinter.CTk` и отвечает за:

- создание главного окна;
- хранение словаря маршрутов;
- регистрацию новых экранов через `register()`;
- переключение экранов через `switch()`;
- уничтожение предыдущей страницы перед показом новой;
- запуск стартового маршрута.

Каждый экран является наследником `ctk.CTkFrame` и получает два обязательных аргумента: родительский контейнер `master` и ссылку на главное приложение `app`. Для перехода между экранами используется вызов:

```python
self.app.switch("login")
```

Дополнительные параметры можно передавать именованными аргументами:

```python
self.app.switch("login", prefill_login=username)
```

Параметр `prefill_login` пока передаётся, но экран входа его не обрабатывает. Это место подготовлено для дальнейшего развития.

## Маршруты экранов

Маршруты задаются в `src/forms/page_register.py`:

| Имя маршрута | Класс | Назначение |
| --- | --- | --- |
| `testview` | `testview` | Текущий стартовый экран-заготовка |
| `login` | `Authorisation` | Форма входа |
| `signup` | `Registration` | Форма регистрации |

Стартовый экран задаётся переменной:

```python
init_page = "testview"
```

Чтобы приложение сразу открывало форму входа, измените её на:

```python
init_page = "login"
```

Чтобы добавить новый экран, импортируйте его класс и добавьте запись в `routes` либо зарегистрируйте его после создания приложения:

```python
app.register("dashboard", Dashboard)
```

Регистрация должна произойти до вызова `app.init_page()` и до перехода на соответствующий маршрут.

## UI-тема и переиспользуемые компоненты

В `src/ui/theme.py` централизованы:

- режим отображения `dark`;
- цветовая тема `blue`;
- фон и основные цвета;
- размеры полей и кнопок;
- отступ `PAD`;
- функция `make_entry()` для единообразных полей;
- функция `make_button()` для единообразных кнопок;
- функция `make_error_label()` для сообщений об ошибках.

Текущие основные размеры:

| Константа | Значение | Назначение |
| --- | --- | --- |
| `ENTRY_WIDTH` | `280` | Ширина поля и кнопки |
| `ENTRY_HEIGHT` | `38` | Высота поля |
| `BUTTON_HEIGHT` | `38` | Высота кнопки |
| `PAD` | `8` | Базовый отступ в формах |

Для изменения внешнего вида приложения в первую очередь редактируйте `src/ui/theme.py`, а не отдельные формы. Это позволяет сохранить единый стиль экранов.

## Конфигурация окна

В `conf/app.py` задаются:

```python
self.geometry("600x400")
self.minsize(600, 400)
self.maxsize(1200, 900)
```

Измените `geometry`, если нужен другой начальный размер. `minsize` и `maxsize` ограничивают изменение окна пользователем.

Файл `conf/conf.json` сейчас пуст и не участвует в запуске. Его можно использовать для пользовательских настроек, адресов API, параметров интерфейса или других значений, которые не должны быть жёстко зашиты в коде. Для секретов JSON-файл в репозитории использовать не следует.

## Что пока не реализовано

1. Пользователи не сохраняются после завершения приложения.
2. Реальная проверка логина и пароля отсутствует.
3. Нет базы данных и API-клиента.
4. Маршрут `dashboard` вызывается после успешного входа, но не зарегистрирован.
5. Переданный параметр `prefill_login` ещё не заполняет поле логина автоматически.
6. Стартовый `testview` является экспериментальной заготовкой и не представляет полноценный dashboard.
7. `src/modules/api.py` пока пуст.
8. `conf/conf.json` пока пуст.
9. Автоматические тесты отсутствуют.
10. Пароль демонстрационной учётной записи находится в исходном коде и не должен использоваться в реальном приложении.

## Рекомендуемый порядок развития

### Подключение реальной авторизации

1. Выберите источник данных: SQLite, PostgreSQL, удалённый API или другой сервис.
2. Создайте отдельный слой доступа к данным вместо запросов из UI-классов.
3. Храните только хеши паролей, например через `bcrypt` или аналогичный проверенный механизм.
4. Замените демонстрационное условие в `Authorisation.on_login()` вызовом слоя авторизации.
5. Обрабатывайте ошибки сети, недоступность сервера и неверные ответы API.
6. Не сохраняйте пароли в логах и не выводите их в консоль.

### Добавление dashboard

Создайте класс `Dashboard` на базе `ctk.CTkFrame`, добавьте его в `page_register.py` и оставьте переход:

```python
self.app.switch("dashboard", username=login)
```

В конструкторе dashboard можно принять имя пользователя:

```python
class Dashboard(ctk.CTkFrame):
    def __init__(self, master, app, username=None, **kwargs):
        super().__init__(master, **kwargs)
```

### Автозаполнение логина

Чтобы использовать `prefill_login`, добавьте в `Authorisation.__init__()` чтение аргумента и вставку значения в `login_entry` после создания поля. Значение нужно очищать и проверять так же, как введённые вручную данные.

### Тестирование

Рекомендуется покрыть тестами чистую валидацию регистрации отдельно от графического интерфейса. Минимальный набор проверок:

- пустые поля;
- короткое имя пользователя;
- некорректный email;
- короткий пароль;
- несовпадающие пароли;
- корректная регистрация;
- успешный и неуспешный вход;
- переключение между маршрутами;
- наличие всех маршрутов, используемых вызовами `switch()`.

## Отладка и типичные ошибки

### `ModuleNotFoundError: No module named 'customtkinter'`

Активируйте виртуальное окружение и установите зависимости:

```bash
source venv/bin/activate
pip install -r req.txt
```

### `TclError` или отсутствие Tkinter

Установите системную библиотеку Tkinter. В Debian/Ubuntu это обычно:

```bash
sudo apt install python3-tk
```

### `KeyError: 'dashboard'`

Успешный вход вызывает маршрут `dashboard`, но этот маршрут отсутствует в `routes`. Добавьте соответствующий класс в `page_register.py` или временно замените переход на существующий маршрут, например `testview`.

### Окно закрывается сразу

Запускайте приложение командой `python main.py` из корня проекта и проверьте, что используется активированное виртуальное окружение. Ошибка запуска будет видна в терминале.

### Изменения темы не сохраняются

Переключатели в `ComponentsDemo` меняют тему только в текущем процессе. Для сохранения выбора запишите значение в конфигурационный файл и применяйте его до создания виджетов.
